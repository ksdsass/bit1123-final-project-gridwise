# GridWise — 10-minute presentation run sheet

Everything four people need to deliver the deck in
`GridWise_Presentation.pptx`. Speaker notes are also inside the .pptx
(View → Notes Page, or the notes pane in Presenter View).

---

## 0. Before you walk in

**Put your names in the deck.** Open `build_deck.js`, edit the `MEMBERS`
array at the top, then:

```
cd presentation
npm install       # first time only
node build_deck.js
```

The order of the array decides who is credited on which slides:

| Index | Owns | Slides |
| ----- | ---- | ------ |
| 1st name | Problem, objectives, overview | 2, 3, 4 |
| 2nd name | Architecture, OOP, Setup demo | 5, 6, 7 |
| 3rd name | Dispatch algorithm, simulation demo, results | 8, 9, 10 |
| 4th name | Features demo, SDG 7, conclusions | 11, 12, 13 |

**Set the laptop up before the session starts, not on stage:**

1. Compile once and leave the app running:
   ```
   javac -d out src/app/*.java src/model/*.java src/service/*.java src/ui/*.java
   java -cp out app.Main
   ```
2. In the app: load the **Cyberjaya, Malaysia — Solar Pilot City**
   example, then leave it sitting on the **Grid Setup** screen.
3. Light mode on, currency on MYR, projector resolution tested.
4. Slide deck open in Presenter View on the second screen.
5. Have `GridWise_Presentation.pdf` on a USB stick as a backup.

**Never compile, never open a file dialog, and never improvise a click
during the presentation.** If the app crashes, keep talking and switch to
slide 8 and slide 10 — they contain a real run, so the argument survives
without the live app.

## 2. Demo scripts

### Demo 1 — Grid Setup (Member 2, 50 s)

1. Preset dropdown → **Cyberjaya, Malaysia — Solar Pilot City**.
2. Click **Load Example**. Point at the table filling with four sources.
3. Say: *"Every row is an EnergySource object. The JTable is just a view
   of the ArrayList behind it."*
4. Type into the form: Solar Farm / `Demo Panels` / `10` / `0.85` →
   **Add Source**. Select the new row → **Remove Selected**.
5. **Leave the fleet as the clean Cyberjaya preset.** The numbers on
   slide 10 depend on it.

### Demo 2 — Run the simulation (Member 3, 50 s)

1. Click **Simulation** in the header, then **Run 24h Simulation**.
2. Read the **Blackout hours** card out loud (it will say roughly 6–9).
3. Read the advice line word for word, then say: *"That sentence is
   generated by our SimulationReport class from the result — we did not
   type it."*
4. Run it a second time. Numbers shift slightly. Explain in one sentence:
   wind strength is drawn fresh every hour, so a plan has to survive a bad
   wind day, not just an average one.

### Demo 3 — Fix the grid (Member 3, 50 s)

1. Back to **Grid Setup**. Add: Hydro Plant / `Demo Hydro` / `50`.
2. Back to **Simulation** → **Run 24h Simulation**.
3. Blackout hours → **0**. Renewable → about **90%**. Cost roughly halves.
4. The point: *"More solar would not have fixed this, because the
   shortfall happens after sunset. We needed something clean that we can
   switch on. The simulator showed us that in one run."*

*Running behind? Skip the clicking and present the numbers on slide 10.*

### Demo 4 — The rest of the app (Member 4, 50 s)

1. Currency dropdown → **USD**. Point at the cost card converting.
2. Click **Export Report**, then open `simulation_report.txt` so the panel
   sees the file exists. *(This is the file-handling mark — do not skip it.)*
3. Mention **Save to File** / **Load from File** in one sentence.
4. Toggle **dark mode** if there is time. Cut this first if there is not.

## 3. Q&A — prepared answers

Whoever owns the section answers. Do not let one person answer everything;
the panel is marking participation.

**"Is this not just a CRUD application?"** — *(Member 1 or 3)*
No. Nothing we display is stored and echoed back. Every number comes out of
the dispatch loop: 24 hourly steps, renewables first, then hydro, then gas,
then a recorded shortfall. Change one source and every figure changes.

**"Where exactly is polymorphism?"** — *(Member 2)*
`GridSimulator` holds `List<EnergySource>` and calls `getOutputMW(hour,
windFactor)` on the reference. Solar answers with a sine curve between
07:00 and 19:00, wind multiplies capacity by the hour's wind factor, hydro
and gas return full capacity. One call, four different answers, chosen at
runtime.

**"Why is `EnergySource` abstract instead of an interface?"** — *(Member 2)*
It carries shared state — `name` and `capacityMW` — with validated setters.
An interface cannot hold fields. The five behaviours that differ between
sources are the abstract methods.

**"Are those real energy figures?"** — *(Member 4, then slide 14)*
The six example grids are inspired by real energy mixes — Kuching on
Sarawak hydro, Copenhagen on offshore wind, Tokyo on gas — but the megawatt
figures are simplified and scaled to city size. They are illustrative, not
measured data, and we say so on our appendix slide.

**"Why do the numbers change every time you run it?"** — *(Member 3)*
Wind strength is a random factor between 0.25 and 0.75 of capacity, drawn
fresh each hour. That is deliberate: a grid plan that only works on an
average wind day is not a plan.

**"How is CO₂ calculated?"** — *(Member 3)*
Each source reports tonnes of CO₂ per MWh. Solar, wind and hydro return
zero; gas returns 0.5. We multiply by the megawatt-hours that source
actually supplied that hour and total it over the day.

**"What if two gas plants have different capacities?"** — *(Member 3)*
The dispatch shares the required output across the plants of that type in
proportion to capacity, then charges cost and CO₂ per plant. That is
`dispatchCost()` and `dispatchCo2()` in `GridSimulator`.

**"Does changing currency change the simulation?"** — *(Member 4)*
No. All tariffs are in ringgit per MWh. The converter is display only, with
fixed rates — the app is fully offline and calls no exchange-rate service.

**"What would you add with more time?"** — *(Member 4)*
Battery storage first, because our own results show the gap is after
sunset. Then real weather data instead of a random wind factor, a full year
instead of one representative day, and automated tests over the dispatch
logic.

**"Which parts are weak?"** — *(anyone — answer honestly, it scores well)*
No storage, no transmission losses, and the dispatch loop still identifies
some source types by string comparison rather than by behaviour. That last
one is the first thing we would refactor.

## 4. Rules for the room

- One speaker at a time; the other three stay still and look at the screen.
- Never read a slide aloud. The slide is the evidence, you are the argument.
- If you go blank, say the action title of the slide — it is a full
  sentence and it is the point you were about to make.
- If a question is outside your section, hand it over by name.
- If you do not know, say so and say what you would do to find out.
- Stay on slide 13 for the whole Q&A.
